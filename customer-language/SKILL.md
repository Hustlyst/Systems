# Customer Language

Write marketing copy in the words your customers already use. Every line it writes can be traced back to at least three real customers, and it learns from your tests which kind of message wins.

## Before you start

1. Read `Resources/rubric.md`, `Resources/edge-cases.md` and `Resources/output-template.md`.
2. Read `MEMORY.md` if it exists: the bank for each segment, the last copy scores, and the logged test results. With no `MEMORY.md`, say this is a first run.
3. Ask which segment this is for, if the business has more than one kind of buyer.
4. Remind the person once to remove customer names and personal details from the sources.

## Run 1: Build or update the bank

**Trigger:** "build a language bank", "mine our reviews", "update the bank".

### Step 1. Collect sources

Ask for raw customer words, as many sources as possible, from more than one kind: sales call transcripts, reviews (including competitors'), survey answers, support tickets, community posts. Aim for at least 30. Offer to read connected tools, such as a meeting recorder or a help desk. Read only.

Label every source, for example "Call 4", "Review 12" or "Survey 7", and note its kind.

### Step 2. Extract quotes

Read the sources in batches of about ten. Pull every useful quote into one of the six groups in the rubric.

- Quote word for word. Never tidy, shorten or improve a quote.
- Keep the label and the speaker's role on every quote.
- Skip anything your own team said, and praise with no detail.

### Step 3. Find the patterns

Across all quotes, group the ones that say the same thing. Count separate sources and source kinds. Apply the pattern rule in the rubric: at least three sources, from at least two kinds.

### Step 4. Compare with the existing bank

If `MEMORY.md` has a bank for this segment, mark each pattern as new, stronger, unchanged or fading. A pattern not seen in the last two updates is fading.

### Step 5. Save

Write the bank update in the shape set by `output-template.md`. Save the patterns, counts and clearest quotes to `MEMORY.md`. This skill owns the bank and may update it without asking. Other changes to `MEMORY.md` need a yes.

Without a `MEMORY.md`, print the bank at the end and ask the person to keep it for next time.

## Run 2: Audit current copy

**Trigger:** "audit our copy", "score our homepage", "how customer-led is this".

1. Ask for the copy: a homepage section, an ad set, an email, a sales deck slide.
2. Mark every line using the scoring table in the rubric.
3. Give the copy score, and the last score for the same asset if `MEMORY.md` has one.
4. Name the three lines to fix first, starting with jargon in the headline.
5. Save the score to `MEMORY.md`.

## Run 3: Rewrite

**Trigger:** "rewrite this in customer words", "rewrite our homepage".

1. Use only patterns from the bank. Follow the rewriting rules in the rubric.
2. Lead with the group that has won most often in logged tests. With no test history, lead with the strongest pain or trigger pattern, and say that this is a starting choice.
3. Under every new line, show the supporting quotes and the source count. These stay in the draft and come out of the final copy.
4. Keep the original length unless asked.
5. Write a test plan: what to compare, where, until when, and what counts as success.
6. Add a task to log the result on the test's end date.

## Run 4: Log a test result

**Trigger:** "log a copy test", "the test finished".

1. Ask which versions ran, where, for how long, and the result in numbers.
2. Record which group each version led with.
3. Save it after the person says yes.

## Run 5: Learn what wins

**Trigger:** "what wins with our audience", or once a quarter.

This needs at least four logged tests. With fewer, say how many more are needed and stop.

1. Count, per group, how often the version leading with it won.
2. Report the pattern in one plain sentence, with the counts.
3. Note any test too small to trust, such as one with only a few dozen visitors, and leave it out of the count.
4. Save the finding after the person says yes, so future rewrites lead with the winning group.

## Rules that always apply

- Word for word, always. A paraphrase is not a customer's language.
- A pattern needs three separate sources. One vivid quote is a lead, never a pattern.
- Never publish a customer's quote as a testimonial without their permission.
- Read only from connected tools. Never publish, send or change anything without an explicit yes.
- When customers value something the strategy does not lead with, show the evidence and leave the decision to the person.
