# Value Pricing

Price a project from what it is worth to the client, with the maths shown, three options to choose from, and a floor you never go below.

## Before you start

1. Read `Resources/rubric.md`, `Resources/edge-cases.md` and `Resources/output-template.md`.
2. Read `MEMORY.md` if it exists: the reader's floor settings, past proposals with their outcomes, and the price-to-value shares calibration has found. With no `MEMORY.md`, use the starting shares in the rubric and ask for the floor.
3. Remind the person once to describe the client instead of naming them, if their agreements require it.

## Run 1: Price a project

**Trigger:** "price this project", "how much should I charge".

### Step 1. Collect the material

Ask for:

1. The discovery call notes or transcript, including any numbers the client mentioned: volumes, team size, revenue, time lost, deadlines, what they tried before.
2. The reader's cost to deliver the core work: their own time, any subcontractors and tools.
3. Their floor, if it is not already in `MEMORY.md`.

If the notes contain no figures at all, follow the "no numbers" case in `edge-cases.md` and stop there.

### Step 2. Build the value case

Work out the three numbers in the rubric: the cost of the problem today, the value of solving it, and the cost of the alternatives.

- Show every calculation step by step, with the source of each figure.
- Mark every assumption with a low and a high estimate, its source and the question that confirms it.
- Use the low estimates for pricing.
- Count each piece of value once.

### Step 3. Build three options

Follow the option table in the rubric. Use the price-to-value shares from `MEMORY.md` if calibration has set them. Otherwise use the starting shares.

- Never price an option below the floor.
- Give each option its result line, what it includes, what is not included and a timeline.
- If the value cannot support option 1 above the floor, say so, and suggest a smaller scope or a polite no.

### Step 4. Check before it goes out

- Pick one calculation and show it to the person to redo by hand.
- Compare option 2 with similar past projects in `MEMORY.md`, and flag a large jump.
- List the assumptions that must be confirmed with the client before prices are sent.

### Step 5. Prepare the conversation

Write the two-minute opening from `output-template.md`: the cost of the problem in the client's words, then the options from highest to lowest, then one question. Then list the three objections the client is most likely to raise, each with a calm answer that keeps the price and adjusts scope if needed.

### Step 6. Save and set the follow-up

Write the value case, the options and the conversation in the shapes set by `output-template.md`. The value case and the floor are for the reader only.

Save the proposal to `MEMORY.md`: the client description, the value range, the three prices and their shares of value, and the date. This skill owns the proposal log and may write it without asking. Other changes need a yes.

Add a task to log the outcome:

```text
- [ ] Log the outcome of the furniture shop proposal (due 2026-11-30)
```

Without a `MEMORY.md`, print the proposal line at the end and ask the person to keep it.

## Run 2: Log an outcome

**Trigger:** "log a proposal outcome", "they chose option 2", "we lost the proposal".

1. Ask which option was chosen, or whether it was lost, and the reason in the client's words if known.
2. Once the project has ended, ask whether the client got the result, and how close the real value came to the estimate.
3. Save it after the person says yes.

## Run 3: Calibrate

**Trigger:** "calibrate my pricing", or once a quarter.

This needs at least 8 logged proposals, including at least 2 lost. With fewer, say how many more are needed and stop.

1. **Win rate per option:** how often each option was chosen, and how often proposals were lost.
2. **The real share of value:** the average share of first-year value at which the reader wins. Suggest replacing the starting shares with it.
3. **Value accuracy:** for finished projects, how the real result compared with the estimate. If results often fall short, suggest lower low estimates.
4. Show the findings in a short table with one plain sentence each.
5. Save the new shares only after the person says yes.

## Rules that always apply

- Only the client's own numbers are facts. Everything else is an assumption with a question attached.
- Price on the low estimates until the client confirms.
- Never price below the floor, and never show the floor to the client.
- Show every calculation, so the person can check it.
- Never send a proposal, email or invoice without an explicit yes.
